Getting started

On any page, press ] then a letter to jump to the next match, or [ then the letter for the previous one. Press ? to see every key.

  • ]b next button
  • ]h next heading
  • ]1–]6 heading by level
  • ]l next link
  • ]j next form control
  • ]] repeat the last jump
  • \b highlight all buttons
  • \\ rotor
  • Enter focus it
  • Esc clear

A jump only moves the highlight. Focus stays where it was until you press Enter, so jumping to a text field never starts typing into it. Squarb ignores your keys while you're typing in a field. Press Esc to leave the field.

What counts as a button

Squarb never looks at tag names or class names. It computes each element's role and accessible name with the same rules browsers use to build the accessibility tree. A <button>, an <input type="submit"> and a <div role="button"> are all buttons. A <div class="btn"> isn't one.

It also skips the things a screen reader skips: anything inside aria-hidden="true" or inert, anything not rendered (display: none, hidden, closed dialogs and popovers), and anything outside an open modal dialog. Visually hidden text, such as a .sr-only skip link, is still reachable and is labelled "visually hidden".

The upshot: if a key can't find something on your page, a screen reader user probably can't either.

"Looks clickable but has no button role"

This element acts like a control. It has a click handler, an onclick, a tabindex, or a pointer cursor. But nothing tells assistive tech that it's a control. Screen readers announce it as plain text, voice control can't target it by name, and keyboard users often can't reach it or press it.

Before

<div class="btn" onclick="save()">
  Save
</div>

After

<button type="button" onclick="save()">
  Save
</button>

A real <button> gives you focus, Enter and Space handling, and the right role for free. If it navigates to another page, use <a href> instead. If you really can't change the element, add role="button", tabindex="0" and a keydown handler, but the native element is less work.

This is a heuristic. A pointer cursor on a decorative card, or a click handler used only for analytics, can trigger it. If it's wrong, it's wrong. It's there to help you spot real problems, not to score your page.

"button (unnamed)"

The element has the right role but no accessible name, so a screen reader says only "button". This usually happens with an icon-only control.

Before

<button>
  <svg>…</svg>
</button>

After

<button aria-label="Close">
  <svg aria-hidden="true">…</svg>
</button>

Visible text is the best name, because everyone sees the same words. Otherwise use aria-label, aria-labelledby, alt on images, or a <label> for form fields.

Heading levels

Screen reader users often skim a page by its headings, much as you skim the bold text. Going from an h2 straight to an h4 suggests a missing section. A page with no h1 has no clear title. Pick levels for the outline, then style them however you like.

Landmarks

Landmarks such as <main>, <nav>, <header> and <footer> let people jump past repeated content with one key (]d here, the Landmarks rotor in VoiceOver, D in NVDA). Every page should have exactly one <main>. A <section> or <form> only becomes a landmark once it has a name, for example with aria-labelledby pointing at its heading.

Frames

Squarb includes same-origin iframes in navigation order, as if their content were inline. It can't read cross-origin iframes, such as embedded videos, payment fields or ads, so it skips them. A screen reader can still read them.

Now try it with a real screen reader

VoiceOver (macOS): Cmd-F5 turns it on. VO is Control-Option (or Caps Lock). VO-Q toggles single-key Quick Nav, and then B, H, L, J, T, X, G and 1–6 jump just like ] + letter (add Shift to go back). VO-U opens the rotor.

NVDA (Windows): browse mode is on by default. Press a letter alone, or Shift + letter for previous. Squarb's e, c, r, d, i and f come from NVDA. NVDA+F7 opens the elements list.
